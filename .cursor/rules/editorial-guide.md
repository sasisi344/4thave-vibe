# 4thave Vibe: Editorial Guide (統合版)

## 1. アイデンティティとトーン（Persona）

- **著者**: さしし（sasisi344）
- **トーン**: 親しみやすく丁寧（です・ます調）。ビジネスライクではなく、友人に話しかけるような距離感。
- **一人称**: 「私」「自分」「ワイ」を文脈で使い分け、徹底的に「感情」と「主観」をフィルターにする。AI的な客観まとめは不要。

## 2. 記事構成ルール（Short-form & Rhythm）

- **毎日投稿・短文構成**: 1記事300〜600文字程度の「気づき」を届ける。
- **スマホ最適化（SXO）**:
  - 1行40〜60字以内。
  - 2〜3文ごとに空行を入れて「呼吸できるスペース」を作る。
  - **強調**: 本番公開用では `**` ではなく `<strong>強調内容</strong>` を使用する。
- **ノーイメージ方針**: サムネイル（cover）や本文画像は原則作成しない。テキストのリズム（箇条書き、引用 `>` など）で視覚的単調さを防ぐ。
- **結び**: 必ず「で、自分はどう思ったか？」という独自の解釈や未来への提案で締める。

## 3. カテゴリとフロントマター

- **シンプル構成**: フロントマターは以下の5項目に限定する。
  - `title`: 読者の目を引くフックのあるタイトル。
  - `publishDate`: 公開日（YYYY-MM-DD）。
  - `category`: Jurnal（原則これのみ）
  - `tags`: 検索用タグ。
  - `description`: 検索結果に表示される短い要約。

## 4. `_draft` からSNS投稿向けに清書するWorkflow（追加運用）

- このセクションは、上記ルールとは別に `_draft` 配下の文書を **Threads / X 向け短文投稿**へ変換するときのみ適用する。
- **トーンマナー準拠**: Persona（著者・語り口・主観重視）は本ガイドの `1. アイデンティティとトーン` を必ず継承する。
- **投稿形式**: `単ポスト` または `複数スレッド` の2種類を用意し、清書前に必ずどちらかを選ぶ。

### 4-1. 清書開始時の確認質問（必須）

- 清書開始時に、次の質問を必ず投げる。
  - 「SNS投稿の形式を選んでください：`単ポスト` / `複数スレッド`（未指定なら文字量で自動判定します）」
- ユーザーが明示指定した場合は、その指定を最優先する。

### 4-2. 分岐判定ロジック

- **優先順位**
  1. ユーザーの明示指示（単ポスト or 複数スレッド）
  2. 元ドラフトの文字量による自動判定
- **自動判定の目安（元ドラフト本文）**
  - `〜280文字`: 単ポスト優先
  - `281〜600文字`: 単ポストを基本に、文脈が分割向きなら複数スレッド提案
  - `601文字〜`: 複数スレッド優先

### 4-3. Workflow A: 単ポスト（Threads / X 共通）

- 目的は「一読で刺さる1メッセージ」に圧縮すること。
- 構成テンプレート：
  1. フック（違和感・問い・体験の断片）
  2. 本文（気づき1点に絞る）
  3. 結び（自分の解釈 or 次アクション）
- 運用ルール：
  - 1投稿1テーマ。論点を増やしすぎない。
  - 改行でリズムを作る（2〜3文ごと）。
  - 必要なら末尾に軽い問いかけを置いてもよい。

### 4-4. Workflow B: 複数スレッド

- 目的は「文脈を保ったまま、短文連投で理解を深める」こと。
- 構成テンプレート（3〜7投稿目安）：
  1. 1投目: 結論 or 問題提起（全体の入口）
  2. 2〜N-1投目: 背景・具体例・感情の揺れ・学び
  3. 最終投: 自分の見解と次の一歩
- 運用ルール：
  - 各投稿は単体でも意味が通る1メッセージにする。
  - ただし全体では、前後の流れで読み味が強くなるよう接続する。
  - 冗長な説明より、体験ベースの具体を優先する。

### 4-5. 最終出力時の明示

- 清書結果の先頭で、どちらのWorkflowを採用したかを明示する。
  - 例: `採用Workflow: 単ポスト（理由: ユーザー指定）`
  - 例: `採用Workflow: 複数スレッド（理由: 元ドラフト 730文字のため）`
